# 录音提速 · 课后修图 · 思考强度

日期：2026-10-22

## 判断先于功能

这一轮改动的起点不是"加功能"，而是把定位收窄了一次。

原本以为这是个"复习工具"——期末翻出来重听。但真实场景是**补课**：上课走神了几分钟，事后要精确找回那一段，听着录音、对着 AI 讲解弄懂。这跟"整门课复习"是两回事，前者要分钟级定位，后者要课程级汇总。

场景一变，优先级就全变了：

- 录音时唯一重要的事是**别错过**，所以拍照必须快到没有等待
- 修图、写字、发送这些动作，都可以推迟到课后
- 既然要修图，就不能在录音结束的瞬间把原图发给 AI

## 四处改动

### 1. 长按快拍

录音页的"拍照并标记"从一个 M3 `Button` 改成自绘 `Box + combinedClickable`（`Button` 只暴露 `onClick`，挂不下长按）：

| 手势 | 行为 |
|---|---|
| 短按 | 打开标记面板，可裁剪、可写字 |
| 长按 | 直接进相机，拍完**跳过裁剪**立即入库 |

录制时走完"拍照 → 裁剪 → 写字 → 保存"四步，老师早讲过去了。长按这条路只保证"这一页被记下来了"。

两条相机路径都要判 `quickCapture` 标志：系统相机（`TakePicture`）和应用内相机（`PendingMarkerStore.capturedPath`）。进相机又退出来没拍的，标志也要清掉，否则下一次短按会被当成快拍。

按钮下方加了一行提示："长按直接拍，不裁剪，课后统一修"——新手势没有提示等于没有。

### 2. 取消自动发送

删掉两处自动发送：

- `RecordingService`：停止录音后的 `enqueueAutoSend`
- `RecordApp`：崩溃恢复后的补发

原图直接送给 AI，之后再改图就白花钱了。发送入口统一到回放页：

- 有从未发送的 → 「发送全部」
- 只有失败的 → 「全部重发」
- 两者都有 → 拆成「只重发失败」+「发送全部」

停止确认框的文案也跟着改了，明确告诉用户"课后到回放页点发送全部"。

### 3. 课后修图

回放页的看图弹窗右上角加了一个裁剪按钮（`Icons.Filled.Crop`）：

```
点开图 → 裁剪 → UCrop → 替换原图 + 标记退回"待发送"
```

关键在于**替换后要把标记退回 `AI_PENDING`**。图变了，之前的讲解就对不上了，留着旧讲解比没有更糟。

- 新文件写入 `images` 目录，旧文件删除（已经没有引用）
- 清 `PlaybackViewModel.imageCache`
- `imageVersion` 自增，让已展开的卡片重新拉一次图片列表

### 4. 思考强度

`AiConfig.reasoningEffort`，四档：`off / low / high / max`。

DeepSeek 官方参数：

```json
{ "thinking": { "type": "enabled" }, "reasoning_effort": "high" }
```

两个坑：

1. **thinking 默认是开启的**。想关必须显式下发 `"type": "disabled"`，不发参数等于没关。
2. **不是所有 OpenAI 兼容服务都认这两个字段**，硬塞会被 400 掉。所以按 host 判断，只在地址里含 `deepseek` 时下发，而不是让用户再去配一个"兼容模式"开关。

AI 配置页用四个 FilterChip，选中档位下方给一句对应的说明（"讲解课件照片通常够用"这种），而不是四个光秃秃的档位名。接口地址不是 DeepSeek 时，直接标红提示此项不生效。

## 补上的一个洞

取消自动发送带来了新的失败模式：**用户忘了手动发**。

所以首页卡片的副标题必须自己把这件事说出来：

```
3 个标记 · 2 个待发送        ← 琥珀色 + 时钟图标
3 个标记 · 2 待发送，1 个失败  ← 红色
```

原来的文案是 `markerFailed == 0 → "全部已讲解"`，在 pending 长期存在的新流程下会**谎报进度**——这条判断必须先改。

## 遗留

- 首页只有文案提示，没有"一键发送全部"的入口，仍要进回放页
- 长按快拍的图没有裁剪，如果用户从不修图，发给 AI 的是相机原图（体积大、可能有透视变形）
- 思考强度目前只对 DeepSeek 官方端点生效
