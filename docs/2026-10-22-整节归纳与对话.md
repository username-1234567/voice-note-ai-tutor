# 整节归纳 · 整节对话 · 静音提醒 · 待复习

日期：2026-10-22

## 1. 搜索覆盖多轮对话

`HomeViewModel.allSections` 原来只 combine 了两路数据（录音 + 标记），搜索文本里只有：

```kotlin
m.userText?.let { append(it) }
m.aiResponse?.take(500)?.let { append(it) }
```

`m.aiResponse` 是**首轮**讲解。你在追问里问过、AI 答过的内容，搜关键词是查不出来的——而这恰恰是最可能被记住的：你会记得"我问过一个关于迁移率的问题"，不会记得那节课第几分钟。

改为三路 combine，把 `MarkerTurn.question / answer` 也拼进索引：

```kotlin
combine(
    recordingDao.observeActive(),
    markerDao.observeAll(),
    markerTurnDao().observeAll(),
) { recs, markers, turns -> ... }
```

## 2. 这节课：提纲 + 对话

回放页在播放器下面加了一张可折叠的卡片，折叠时只占一行。

**生成提纲**（`generateDigest`）：

1. `buildCourseContext()` 把每个标记压成"时间点 + 备注 + 讲解前 800 字"，总长上限 2 万字
2. 一次 `DeepSeekClient.chat`（流式，边走边渲染）
3. 结果写入 `recording_digests`，一个 recordingId 一份，重新生成即覆盖

Prompt 强制三段结构：

```
## 核心脉络   3–6 条，按课堂顺序，每条一句话
## 关键概念   术语表，只收材料里出现过的
## 自测问题   三个，分别考记忆/理解/应用，不给答案
```

最后一句是"材料里没提到的内容不要补充，宁可少写"——不写这句，模型会自己补课外知识，复习提纲就变成了通用科普。

**整节对话**（`ask`）：

- 存入 `recording_chats`，再读全部历史构造 messages
- system 里塞三样东西：角色约束、已生成的提纲（≤4000 字）、课程材料（≤12000 字）
- 只带最近 6 轮、每条截断 1500 字——材料已经占了大半上下文，历史再长会顶爆 token
- 提示词明确要求"材料里没有的就说「课上没记到」，不要编造"

对话入口只在**已有提纲**后开放：没有材料时它答不出有内容的话，只会变成通用 ChatGPT。

## 3. 静音/走远提醒

`RecordingService` 的心跳里已经读了 `maxAmplitude`（声纹环在用）。

一个容易踩的坑：**`maxAmplitude` 读取后峰值归零**，所以整个心跳只能读一次。原来的写法是在 `level` 的计算里读，静音检测如果各读各的，第二个拿到的一定是 0。

改为先取一次 `rawAmplitude`，声纹环和静音检测共用：

```kotlin
val rawAmplitude = if (paused || interrupted) 0 else runCatching { recorder?.maxAmplitude ?: 0 }.getOrDefault(0)
checkSilence(!paused && !interrupted, rawAmplitude)
```

判定：连续 60 秒峰值 < 1000（满量程 32767 的 3%）提醒一次。声音恢复后重置，允许之后再提醒。提醒经 `RecordingBus.levelWarning` 推到录音页 Snackbar，停止录音时清理。

阈值取 3% 而不是更低：教室底噪（空调、翻书）一般在几百，1000 能滤掉底噪又不会漏掉"老师走远了"。

## 4. 标记待复习

语义先定死：**"这条我还没弄懂，回头要再看一遍"**，不是收藏。所以用星标不用心形。

- `Marker.needsReview: Boolean`
- `MarkerDao.setNeedsReview(id, value, now)` —— 只 UPDATE 这一列，不整行覆盖，避免把并发生成的讲解写没
- 卡片标题行右侧：展开时始终可见（可以标），收起时只在已标记时显示（提醒）

交互上没有做筛选入口。加筛选会改动列表结构，而真实使用频率未知——先让星标跑一段时间，看它会不会被用起来，再决定要不要做"只看待复习"。

## 5. 数据库

`version 2 → 3`，一次迁移做三件事：

```sql
ALTER TABLE markers ADD COLUMN needsReview INTEGER NOT NULL DEFAULT 0
CREATE TABLE recording_digests (...)
CREATE TABLE recording_chats (...)
```

备份是整库文件打包（`database/app.db`），所以新表自动包含，不需要改 `BackupManager`。旧备份（v2 schema）导入到 v3 时，Room 会走 `MIGRATION_2_3` 补齐。

## 已知限制

- 提纲生成依赖 `buildCourseContext()`，标记越多 prompt 越长。20 个标记以上时首字延迟会比较明显
- 对话失败后 user 消息已经入库，重问会出现一条重复记录。没有做"失败消息重试"
- `MarkdownView` 基于 WebView，卡片里同时展开提纲和对话时会有多个 WebView 实例，低端机上滚动可能掉帧
- 待复习没有筛选、没有跨录音的聚合视图（比如"这门课所有待复习的标记"）
