# 代码审查：bug 与优化点

日期：2026-10-22
范围：全项目（重点：录音服务、设置页、回放页、首页搜索）
结论：**修复 11 处**，提出 7 项优化建议，排除 5 处疑似问题。

---

## 一、已修复

### 1. 手动暂停后，录音会自己恢复 ⚠️ 用户可感知

`service/RecordingService.kt`

音频焦点监听里 `AUDIOFOCUS_GAIN -> doResume()` 是**无条件**的：

```kotlin
// 修复前
AudioManager.AUDIOFOCUS_GAIN -> doResume()
```

复现路径：录音中手动按暂停 → 收到一条微信语音 → 语音播完，音频焦点还回来 → `doResume()` → 录音继续。

用户明明按了暂停，却被系统悄悄撤销。而 `doPause` 本身已经区分了 `TYPE_USER_PAUSE` 和 `TYPE_AUTO_INTERRUPT`，只是恢复时没用上这个区分。

修复：新增 `userPaused` 标志（用户态），焦点恢复时只在 `!userPaused` 时续录。

```kotlin
AudioManager.AUDIOFOCUS_GAIN -> if (!userPaused) doResume()
```

- `doPause(TYPE_USER_PAUSE)` 时置位（放在 `if (paused) return` **之前**——已经因打断暂停时用户再按暂停，也说明"我要保持暂停"）
- `doResume()` 时清除
- `startRecording()` 时重置

### 2. 点完"保存"立刻返回，配置没存上 ⚠️ 数据丢失

`ui/screens/settings/SettingsViewModel.kt`

```kotlin
// 修复前
fun saveAi(config: AiConfig) {
    viewModelScope.launch { container.settings.setAiConfig(config) }
}
```

`viewModelScope` 在页面销毁（`onCleared`）时取消。点保存 → 协程刚启动 → 用户按返回 → VM cleared → DataStore 的 `updateData` 被取消 → 配置丢失。

同文件里的 `exportTo` / `importFrom` 早就注明了要用 `appScope` 的理由（"离开设置页不会取消"），保存配置是同一个问题，只是没人注意到。

修复：`saveAi` / `saveGeneral` / `saveAndTestAi` 的**保存那一步**改走 `container.appScope`；测试连接仍绑 `viewModelScope`（它只更新页面可见状态）。

### 3. 设置页改了一半按返回，静默丢弃 ⚠️ 数据丢失

`ui/components/SecondaryPage.kt`、`AiSettingsScreen.kt`、`DataSettingsScreen.kt`

AI 配置页有 7 个字段、存储设置页有 3 个，全都没有脏检查。填完 API Key 按返回，直接没了，连一句"要保存吗"都没有。

修复：`SecondaryPage` 增加 `unsavedChanges: Boolean`，为 true 时：

- 左上返回键走拦截
- 系统返回键 `BackHandler` 拦截
- 弹"放弃修改？"，破坏性确认

```kotlin
SecondaryPage(
    title = "AI 配置",
    onBack = onBack,
    unsavedChanges = dirty,
    ...
)
```

`dirty` 用 trim 后的值比较，避免"多个空格"被判成有改动。

### 4. 回放页播放器的"首次出场"动画从来没播过

`ui/screens/playback/PlaybackScreen.kt`

```kotlin
// 修复前
LaunchedEffect(Unit) { playerEntered = true }
```

`LaunchedEffect(Unit)` 在页面**组合的第一帧**就执行，那时 `recording` 还是 `null`，界面显示的是 loading 圈。等数据到了、播放器真正出现时，动画早已跑完到 1.0，用户看到的是直接出现。

修复：以数据到位为起点。

```kotlin
LaunchedEffect(recording != null) {
    if (recording != null) playerEntered = true
}
```

### 5. 倍速胶囊切换时宽度瞬跳

`ui/screens/playback/PlaybackScreen.kt`

`AnimatedContent` 自定义了 `transitionSpec` 但没带 `SizeTransform`，导致 "1×" → "1.25×" 时容器宽度直接跳到新尺寸，没有过渡——比不做动画更跳。

修复：

```kotlin
(fadeIn(tween(130)) togetherWith fadeOut(tween(90)))
    .using(SizeTransform(clip = false))
```

`clip = false` 是为了避免过渡中数字被裁掉半个。

### 6. 进度条总时长在未播放时不更新

`ui/screens/playback/PlaybackViewModel.kt`

`ExoPlayer.prepare()` 是异步的，构造完立刻读 `p.duration` 拿到的是 `C.TIME_UNSET`，`coerceAtLeast(0)` 一转就成了 0。之后只有 `onIsPlayingChanged` 会刷新，所以**用户不点播放就一直看不到真实时长**，`seekTo` 的上界也退化成 `Long.MAX_VALUE`。

修复：补 `onPlaybackStateChanged`，`STATE_READY` 时同步一次；顺带补 `onPositionDiscontinuity`，seek 后 UI 位置不用等下一个 200ms tick。

### 7. 点进度条上的标记，卡片可能在屏幕外

`ui/screens/playback/PlaybackScreen.kt`

点进度条上的圆点，代码只做了 `jumpToMarker` + `expandedMarkerId = m.id`。如果那条标记卡在列表下方看不见，用户看到的只有进度跳了一下，会以为"没打开"。

修复：点击后 `animateScrollToItem` 到对应卡片。

```kotlin
private const val MARKER_ITEM_OFFSET = 3  // 播放器 + 重发条 + "标记"标题
```

偏移量是常量并写了注释——`LazyColumn` 再加 item 时要同步改。

### 8. 设置页划不动 ⚠️ 阻断级

`ui/screens/settings/SettingsScreen.kt`

```kotlin
// 修复前
val scrollBehavior = TopAppBarDefaults.exitUntilCollapsedScrollBehavior()
Scaffold(modifier = Modifier.nestedScroll(scrollBehavior.nestedScrollConnection), topBar = { 自绘 Row })
```

`exitUntilCollapsedScrollBehavior` 是给 `TopAppBar` 的 `scrollBehavior` 参数用的，这里顶栏是手写的 `Row`，**behavior 从没被接管过**。

后果：`TopAppBarState.heightOffsetLimit` 停在初值 `Float.NaN`，`heightOffset` 的 `coerceIn(-NaN, 0f)` 等于没有上界限制，于是 `nestedScrollConnection.onPreScroll` 把**每一次上滑的距离整段吃掉**，Column 自己的 `verticalScroll` 一点都分不到。表现就是页面完全不响应上滑。

修复：这套折叠行为本来就不需要（顶栏是固定 23sp 标题），直接删掉 `scrollBehavior` 与 `nestedScroll`。

### 9. 输入法遮挡（全项目此前为 0 处理）

`enableEdgeToEdge()` 之后系统不做 resize，键盘高度必须 App 自己让。此前全项目搜不到一处 `imePadding`：

- 二级设置页的"保存配置"按钮被键盘压住，填完 Key 得先收键盘才点得到
- 课程表页 5 个时间段 × 起止共 10 个输入框，滚不到被遮的那格
- 回放页追问输入框和迷你播放条一起被埋

修复：这四处 `Scaffold` 统一加 `Modifier.imePadding()`，键盘弹起时整页压到键盘上方，底部操作键浮在键盘上、滚动视口同步变矮。

### 10. 迷你播放条多让了一个导航栏

`MiniPlayer` 挂在 `Box(Modifier.fillMaxSize().padding(scaffoldPadding))` 内，而 `Scaffold` 的 `contentWindowInsets` 默认是 `systemBars`，`padding.bottom` 里**已经含了导航栏高度**。播放条自己又加了一次 `navigationBarsPadding()`：

- 整条上飘一个导航栏的距离
- 下方那段既是空白、又是点击死区

修复：去掉 `navigationBarsPadding()`，并把列表底部留白从 96dp 收到 88dp。

### 11. 编辑提问从内联输入框改为弹窗

`ui/screens/playback/PlaybackScreen.kt`

原来点"编辑"会在该轮对话下方展开一个 `OutlinedTextField + 发送 + 关闭` 的 Row：

- 把整张卡片撑高，下面的轮次被推走，编辑时反而看不到上下文
- 和"重命名录音"的编辑体验不一致（那边是弹窗）

修复：改成 `AppAlertDialog` + 多行输入框，`confirmEnabled = editDraft.isNotBlank()`（为此给弹窗组件加了 `confirmEnabled` 参数）。顺带给首页重命名也加了同样的空值保护。

## 二、建议但未做

按影响面排序。

### A. 首页搜索索引每次数据变化都全量重建

`HomeViewModel.kt:49` 的 `searchText` 是 `HomeItem` 的构造参数，每次 Room 发射（新增标记、AI 回复落库）都会对**所有录音**做一遍字符串拼接：

```kotlin
searchText = buildString {
    append(rec.title).append(' ')
    ms.forEach { m ->
        m.userText?.let { append(it).append(' ') }
        m.aiResponse?.take(500)?.let { append(it).append(' ') }  // 每条标记最多 500 字
    }
}.lowercase()
```

100 条录音 × 20 个标记 × 500 字 ≈ 100 万字符，且发生在主线程的组合路径上。录音多了首页会明显掉帧。

建议：`HomeItem` 改存 `List<Marker>` 引用，把匹配逻辑挪到 `sections` 的 `filter` 里按需计算（无搜索时零开销，搜索时可 early-return）。

### B. 备份 zip 含明文 API Key

`BackupManager.kt:62` 的注释自己写明了"settings.json（含 API Key，不加密）"，AI 配置页也有告知文案。所以这是**有意的产品决策**，不是疏漏。

但用户把备份发微信/传网盘时，Key 会跟着走。建议给导出加一个开关（默认不导出 Key），或者导出后单独提示"此文件包含 API Key"。

### C. 更新包下载走 `viewModelScope`，切走页面就断

`SettingsViewModel.downloadUpdate`。下载 20MB 的 APK 期间离开设置页，协程被取消，进度白跑。

建议改 `appScope` + 前台通知，或至少提示"下载中请勿离开"。

### D. `collectAsState` 不是 lifecycle-aware

全项目用的是 `collectAsState()` 而非 `collectAsStateWithLifecycle()`。App 退到后台时 Flow 仍在收集——对 Room 查询影响不大，但对 `RecordingBus` 这类高频流（每 500ms 一次）会持续唤醒。

建议全局替换（`androidx.lifecycle:lifecycle-runtime-compose` 已在依赖里）。

### E. 录音页没有返回拦截

录音中按系统返回 → `popBackStack()` 直接离开页面。录音服务仍在后台跑（不会丢数据），但用户很可能以为"返回 = 结束录音"，然后去通知栏找。

建议：录音中按返回时弹一句"录音仍在后台进行，可在通知栏停止"。

### F. 日期选择器可选未来日期

`HomeScreen` 的 `DatePickerDialog` 没有 `selectableDates` 限制。选明天 → 提示"明天没有录音，已跳到最近的一天"，是个无意义的往返。

建议：`selectableDates` 限制到 `today`。

### G. 弹窗关闭的 120ms 内仍拦截触摸

`AppAlertDialog.close()` 先播退场再回调，这 120ms 里 `Dialog` 窗口还在，会吃掉触摸。时间很短，实际影响有限；如果介意，可以让 scrim 在退场时立即 `pointerInput` 失效。

### H. 22 处空 catch

`RecordingService` 里 `doPause` / `doResume` 的 `catch (_: Exception) {}` 会吞掉 `MediaRecorder.pause()` 失败。如果某机型不支持 pause（API 24+ 才支持，minSdk 29 没问题），用户会看到"暂停了但还在录"。

建议：至少把这些失败写进 `sigcheck.txt` 同级的一个诊断日志，方便真机排障。
