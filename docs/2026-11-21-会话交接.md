### 17. 回到底部悬浮钮（含本轮最深的一个坑）
- 滚离底部 > 40px 出现、回到底部消失；白圆 34px + ˅，贴输入框上方右侧；淡入上浮 200ms 动画；点击回底并恢复流式跟随。
- **根因坑**：SessionView 把 footer 作为 children 传进 MessageList，MessageList 内部才有 `ScrollToBottomContext.Provider`——但 `useContext` 读的是**组件在树上的位置**，SessionView 拿到的是默认空函数。症状极像「点击被吞」：native click、pointerdown 全都正常触发，React onClick 也挂上了，就是没效果。用 CDP（`WebView.setWebContentsDebuggingEnabled` + `adb forward tcp:9222` + Node 原生 WebSocket）逐层排除后定位。修复：回调不走 context，挂 zustand（`scrollFabState.ts` 的 `registerScrollJump`）。**跨层回调（children 传 UI 的场景）一律用 zustand 注册，别用 context 传函数。**
- 调试基建（已验证好用）：`setWebContentsDebuggingEnabled` → `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>` → Node WebSocket 走 CDP：`document.elementsFromPoint` 查命中层、`__reactProps$` 查 React 实际挂的 props、`Input.dispatchMouseEvent` 模拟真实点击。**调试开关已从代码撤除**。
- 本机响应结构与标准 CDP 少一层嵌套（`result` 直接是 RemoteObject），解析时兼容两种。

## 四、已经确立的约定（踩坑换来的）

1. **一次只动一件事。** 用户明确批评过「该这么快能改好吗」。
2. **UI 改动必须看画面。** 没有截图/真机确认不算做完；用户会反复要求「截图看看」。本机 root 后可以 `su -c input tap` 驱动真机自己截图，不用麻烦用户。
3. **先问清现象再改。** 用户报「滑动不了」这种短句时，先确认是哪个滑动，再动手——本次就因此来回返工两次。
4. **不要臆造 UI。** 说过「按住说话，因为你根本没做」——没实现的功能不要摆出来。语音识别已整体砍掉，别再提议；消息长按菜单也因与行内按钮冗余被砍。
5. **别用 sed -i / open('w') 改仓库文件。** CRLF 会被写坏，统一二进制 `open(p,'rb')/('wb')`，改完看 `git diff --numstat`。
6. **别用 python 读 sqlite**：本机安全策略会拦。
7. **改动要落在用户能感知的地方**：比如提示词改了要能在界面里恢复默认、追问要点一下防误触。
8. 价格/计费敏感：误触一次追问就是一次真实计费；已生成的讲解删除不退费——这些都要在 UI 上说出来。
9. **截图先鉴别是官方还是我们的 app**：官方有语音钮 (•))、免责行「仅供参考」；我们无语音钮、免责行「请仔细甄别」。曾把我们的 app 当官方分析过一轮。
10. **尺寸以官方 web CSS 为真值**，不以 app 截图目测为准（MIUI 显示缩放 ≈2.82 会骗人）；官方 CSS 免登录可拉 `fe-static.deepseek.com/chat/static/main.*.css`。
11. **跨层回调（children 传 UI 的场景）用 zustand 注册，别用 context 传函数**——React context 读的是组件树位置，不是元素挂载位置。
12. **官方账号后端的功能（反馈/分享链接/音色/续流/通话）不搬运**：我们只有 API Key，抓包/token 都不可用；可落地差距先对照 API 面再动手。

## 十、2026-11-21 夜续：⊕ 动画、图片编辑器与学术研讨入口（本节取代前文相应结论）

### 18. ⊕ 附件面板过渡动画（官方逐帧实测）

- root 驱动 screenrecord 官方 app，逐帧分析出真值：**打开 ≈150ms 减速**（气泡上滑让位 + 卡片从底缘跟升淡入，卡片行程大于面板高度）、**关闭 ≈100ms**、**图标是 + 刚体旋转 45° 变 ✕**（帧 #293-294 清晰显示斜角中间态）。**前文「⊕ 面板即时出现无过渡」结论作废**（当时测量不完整）。
- 实现：`theme.css` 补齐官方 token（`--ds-ease-in: cubic-bezier(.4,0,1,1)`、`--ds-ease-out: cubic-bezier(0,0,.2,1)`、`--ds-transition-duration-fast: .1s`）；`.attachPanel` 改**常挂载裁剪窗** `.attachPanelWrap`（max-height 展开推动气泡上移 + 卡片 `translateY(36px)` 跟升淡入，开 150ms ease-out / 关 100ms ease-in）；图标恒用 IconPlus 加 `transform: rotate(45deg)`（官方就是刚体旋转）。
- **坑**：`.attachPanelWrap` 在 flex 列容器（align-items:center）里不设 `width:100%` 会缩成内容宽，卡片变窄竖条——装机后用户先看到的那个 bug。

### 19. 图片附件官方化（ImageEditor，本轮最大块）

**官方流程语义（uiautomator dump + root 驱动实测，dp @3.25）**：
- 相机 → 快门 → **全屏编辑器**（圈点默认可画，顶栏 ✕/↶↷/裁剪，hit 区 59×44）→ 裁剪是**独立整页**（角框+边中点 8 手柄、右上「旋转」44dp 高、底部 ✕(放弃) 44×44 + 确认蓝条 279×44，距底 23dp）。
- 编辑器 ✕ = **返回相机 retake**（相机↔编辑器循环，唯一出口是 ↑ 发送）——我们是系统相机做不到循环，**变体：✕ = 应用修改并收起**，丢弃走缩略图 ✕。
- 缩略图点开 = 查看 + 裁剪入口（图四）；图三气泡态：缩略图 **74dp**、删除 ✕ 常显（删除 hit 44dp）、图chips **92×44dp**（缩略图→chips 仅 5dp、chips→输入行 35dp）；**无操作时 ↶↷ 隐藏**，有操作才出现。
- 图片区 y129-630，chips 行 y658-702，气泡内容 y746-804；编辑器内无免责行、无 ⊕ 面板。

**我们的实现（`components/chatInput/ImageEditor.tsx` + `.module.css`）**：
- 画布重放架构：ops 序列（stroke/rotate/crop）按序重放，撤销重做 = 回退序列重放；圈点单色蓝 `#5a72e8`，笔宽按显示比例换算；关产物 `toBlob` 换新 File 走 `drafts.replaceDraftAttachment`（取消旧上传任务→换文件→重传，沿用同一附件 id）。
- **层叠三层**：编辑器 overlay z 900、气泡 `.wrapper` z 901、裁剪页 z 902。**欢迎页没有 inputContainer 层叠上下文**，曾用 z -1 让 header 截走了 ✕/裁剪的点击（用户报「裁剪不了」的根因之一）；z 900/901 后两种外层结构（会话页/欢迎页）行为一致。
- **bottomInset（气泡顶边定位）必须 rAF 每帧连续校正**：一次性测量 + ResizeObserver 会拿到「缩略图行隐藏/面板收起前」的中间态，chips 悬空 93dp 的根因；rAF 循环差值 <1px 不触发渲染。
- **画布与裁剪层必须钉进同一个 `.canvasBox` 定位盒**：裁剪层 absolute 在整个黑底区时，画布居中留黑边会导致选框坐标错位（「裁剪成啥样了」的根因）。
- 裁剪态上下预留 64/84px（`CROP_RESERVE_TOP/BOTTOM`，与 `.cropMode .area` 内边距一致），否则竖图顶满时**底部两个角柄被 overflow:hidden 裁掉拖不到**（用户实测报过）；手柄视觉不变、命中区扩到 44px，touch-action:none。
- 快捷 chips（分析一下/解释一下/这是什么/怎么办）：**点击填入不直发**（用户拍板，与追问防误触同口径）；高度曾按官方 44dp 抬高，**用户打回 → 现为 34px/13px**；图三态位于缩略图与输入行之间（margin-top 4px）。
