# 合并发送与单独提示词

日期：2026-10-26

## 需求

发送前可以把多个标记合并到同一次对话里发送，并且能单独编辑对 AI 发送的提示词。

拆开是两件事：

1. **合并**：多个标记的图片进一次请求，共用一条讲解
2. **提示词**：发送前就能改这一条要 AI 怎么讲，而不是发送后再回头改问题

## 为什么值得做

一页课件经常要拍两三张——左半页、右半页、补充的公式、老师的板书。各发各的，模型看不到彼此，只能各讲一段，用户还得自己在脑子里拼。合并之后它面对的是同一处内容，能指出"第二张那个符号就是第一张里的 μ"。

成本也更低：三张图一次请求，比三次请求便宜，且共享一次上下文。

## 数据模型

没有建"合并组"新表，只给 `Marker` 加了两列：

```kotlin
val customPrompt: String? = null,   // 发送前自定义提示词
val mergedInto: Long? = null,       // 并入哪一条的讲解（对方的 markerId）
```

理由是：合并产出的仍然是**一条**讲解，天然有归属。让它落在组首那条标记上（和单条回复存同一个地方），其余成员只记一个指针指过去——不需要第二套 turn/回答的存储结构。

代价是成员不持有自己的 `aiResponse`，所以列表里要能识别"我并入了别人"。这个处理放在卡片里：

```kotlin
if (marker.mergedInto != null) {
    Row { Text("已并入合并讲解"); TextButton("查看") { 滚到组首 } }
} else when (marker.aiStatus) { ... }
```

不重复存回答还有个好处：同一段话不会在列表里出现三四次。

## 发送

`AiSendManager.sendMerged(markerIds, prompt)`：

1. 取组首（选中列表第一个）作为归属
2. 把所有成员的图片合起来、按绝对路径去重
3. 拼问题：`提示词 + 各成员的"涉及知识点" + 一句"这是同一处内容的 N 张图，合起来讲"`
4. 删掉组首原来的 turn0，重建一轮（合并即重做）
5. 流式生成，增量推到组首那张卡上（复用 `_streaming`）
6. 成功后：组首存回答，成员写 `mergedInto` 并把 `aiResponse` 置 null
7. 失败：所有成员一起标失败，错误信息一致

一次请求，一条回答，N 条标记的状态一起变。

## 提示词

两个入口，共用一个对话框：

- **单条**：卡片展开区「发送提示词」，存在 `Marker.customPrompt`，清空即恢复全局
- **合并**：点「合并发送」时弹出，只作用于这一次请求，不落库

`generateTurn` 里取值顺序改成：

```kotlin
val basePrompt = marker.customPrompt?.takeIf { it.isNotBlank() } ?: ai.prompt
```

和「涉及知识点」的区别要留住：`userText` 说的是"这页讲什么"，`customPrompt` 说的是"要 AI 怎么讲"。

## UI

发送条上，未发送 ≥ 2 个时多一个「合并」按钮 → 进入选择模式：

- 卡片左侧出现勾选圈，点卡片是选中而不是展开
- 底部出现固定条：「已选 N 个 / 取消 / 合并发送」
- 选够 2 个才能发

「合并发送」弹窗写提示词 → 确认 → 退出选择模式。

## 一个必须处理的边界

成员被并入之后，如果用户又单独点它的「重新生成」，它会生成自己的回答——但 `mergedInto` 还指着组首，界面会同时显示"已并入合并讲解"和一段回答。

所以 `generateTurn` 开头先清这个字段：

```kotlin
db.markerDao().clearMerged(marker.id)
```

这条要自己讲了，"并入"就不再成立。
